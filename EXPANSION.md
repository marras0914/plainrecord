# Expansion: two new modules

**Status: planning, November 2026.** Nothing here has shipped. The specs are
[ECONOMY.md](ECONOMY.md) and [FAITH.md](FAITH.md); this file covers what they
share and how they fit into this repo.

Two additions to rightnleft.com:

| Module | Question it answers | Scope |
|---|---|---|
| Economy | What happened to the economy while each party held power? | National, 1949 to now |
| Faith | How do party platforms line up with what Christian traditions officially teach? | Texas and national platforms |

Both follow the rule the quiz already follows: **the reader judges the material
before seeing any party label, and every figure traces to a primary source.**
Neither module hands out a verdict. `outcomes.ts` sums up the stance: an outcome
is not a causal claim, and a panel where every number indicts reads as advocacy.

Nothing in this plan can ship yet. The 3 November 2026 election has passed,
so `scripts/check_election_dates.mjs`, the first step of `npm run build`,
fails on every deploy, and has done since 4 November. That gate is right to

Before any module work:

   `/hoja` pages and PDFs, or replace them with an undated version. Remove
   `check_election_dates.mjs` from the build in the same commit that removes
   the last dated page, not before. The gate goes when its subject goes.
2. **Race pages** become a record of a finished race: say the election is
   over and link the official results. Don't leave pre-election wording up.
3. **Plan the 90th Legislature.** It convenes 12 January 2027. The 89th
   session's votes stay true as a record, but "Your rep" pages will name
   people who no longer hold the seat. Decide whether those pages say "your
   representative in the 89th Legislature" or follow the new members, before
   January rather than after.

Step 0 is upkeep of the existing site, not part of either module, but it sits
first because a module that can't deploy hasn't launched.

## The scope question comes first

The site currently describes itself as "How Texas legislators actually voted."
The economy module is national and is about presidents, Congresses and Fed
chairs, not Texas House members. The faith module is about party platforms,
not roll calls. Both are reasonable extensions, but they change what the site
is, so decide this deliberately:

- **Option A: sections of rightnleft.com.** Add them to the nav and footer in
  `_site_nav.mjs`. The nav is five items on purpose (one per kind of page a
  reader comes for), so two more items means revisiting that rule.
- **Option B: a "Context" hub.** One nav item, `/context`, linking to both
  modules. This keeps the nav at six and frames both modules as background to
  the quiz rather than new products.
- **Option C: a separate sub-brand.** Their own landing page, linked from the
  footer only.

Option B is the recommended starting point. It's the cheapest to undo.

**Decided 12 Nov 2026: option B.** "Context" took the Races slot, so the nav
stays at five. `/context` launched holding the three 2026 race pages as
background, since the races are over, and the economy and faith sections join
it as they ship. `/races` and `/contiendas` redirect permanently to `/context`
and `/contexto`.

## How a module fits this repo

There's no client framework to extend. The quiz is plain TypeScript in
`src/main.ts`, and everything else is static HTML generated by
`scripts/build_*.mjs`. The new modules follow the static-page pattern, not the
quiz bundle, so the 36 KB quiz bundle doesn't grow.

| Layer | Pattern to copy | New module files |
|---|---|---|
| Hand-curated, sourced data | `outcomes.ts`, `stated_positions.ts` (root, typed, reviewable as a diff) | `econ_control.ts`, `econ_context.ts`, `faith_positions.ts`, `faith_verses.ts` |
| Fetched raw data | `scripts/ingest_*.ts` writing to `WORK_DIR` | `scripts/fetch_fred.ts` writes `data/fred/*.json` |
| Pure computation | `scoring.ts`, `valence.ts` (no I/O) | `econ.ts` |
| Shipped payload | `scripts/export_quiz_data.ts` writing to `SHIP_DIR` | `scripts/export_econ.ts`, `scripts/export_faith.ts` |
| Pages | `build_charts.mjs` + `_page_shell.mjs` `document_()` | `scripts/build_economy_pages.mjs`, `scripts/build_faith_pages.mjs` |
| Charts | `_charts.mjs` SVG, rendered at build time | Same helpers, plus a timeline band chart |
| Interactivity | `public/js/zip-lookup.js` passed as `scripts: [...]` | `public/js/econ-blind.js` (and `faith-blind.js` in the later faith phase) |
| Tests | `*.smoke.ts` registered in `scripts/run_tests.mjs` | `econ.smoke.ts`, `faith.smoke.ts` |
| Browser checks | `scripts/verify_site.mjs` | New assertions, listed below |
| Spanish | `i18n/classroom.json` with per-string `status` | `i18n/economy.json`, `i18n/faith.json` |

### Rules that carry over unchanged

- **`WORK_DIR` vs `SHIP_DIR`.** Raw FRED pulls go in `data/`. Only the export
  scripts write to `public/data/`. The header of `scripts/paths.ts` says
  `public/data/` holds "only quiz_89R.json", which was already out of date
  (`votes_89R.json` and `election_tx.json` ship from there too). Rewrite it to
  list what ships and which script writes each file, the new exporters
  included.
- **The build never touches the network.** Fetched data is committed (as
  `public/og.png` is), so a Vercel deploy can't fail because FRED is down and
  the build doesn't need an API key.
- **CSP stays as it is.** `script-src 'self'` with no inline scripts, so each
  blind round is a file under `public/js/`. No chart libraries and no CDNs.
  Charts are SVG strings rendered at build time.
- **No new endpoints.** Neither blind round posts anything. If an opt-in tally
  is wanted later, it follows `api/_tally.ts`: aggregate counters only, with
  answers recomputed on the server.
- **Spanish gate.** The page builders refuse to write Spanish while any string
  in their i18n file isn't `status: ok`, as `build_classroom_page.mjs` does.
  Official text (platform planks, denomination statements, FRED series titles)
  stays in its original language with `lang="en"`, for the same reason the
  official bill captions do.
- **Licence.** Our computed figures and prose are CC0. The underlying series
  are US government works (BEA, BLS, Census), but check each FRED series' notes
  for a third-party copyright line before shipping it.

### Reveal data stays out of the blind round

A blind round is only blind if the party labels aren't on the page. Each blind
page ships the unlabeled items, and its script fetches the reveal file only
after the last answer. `verify_site.mjs` asserts that no request for the reveal
file happens before then.

### Neither blind round may have a knob that sets the answer

The quiz learned this the hard way: whatever we choose (which items, which
wording, how answers are summarized) can produce the result we hope for, so
the design has to be able to come out against that hope. In this plan that
means:

- **Economy:** the blind round shows **every completed term**, not a selection.
  There's nothing to pick, so there's nothing to defend.
- **Faith:** the blind round asks readers to match principles to planks, and
  the principles are the site's own wording. Which principles get written,
  and how, would decide which party readers end up matching. So the faith
  module launches with the tradition lens only, where every word on the page
  is a source's. The blind round comes later, under stricter rules.
